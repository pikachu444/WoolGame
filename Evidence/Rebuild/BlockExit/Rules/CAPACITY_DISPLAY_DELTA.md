# 용량 숫자 표시 변경 독립 증분 검증

판정: **새 패키지의 규칙·정의 동등성 및 소스 일치 확인 통과. 추가 제품 수정 요청 없음.**

새 제품 커밋은 `908c8efc4a53977f707ac1bb11f12e4e2d0901a6`, Rebuild 트리는 `5812956235ec49f033f381f95a52204bf17985b1`이다. 새 PCK SHA256은 `351219ac1c7552ef9dfc4b755bd1e8b0bd452a1060ee731e8134ebee7b445090`, APK SHA256은 `bdeadf44dc83b1eb7057cfcb2d1554d9d43d6a3b91fe84d8a4aa55e20653a680`이다.

## 이전 전체 검사와 이번 검사의 구분

[이전 전체 독립 검사](INDEPENDENT_BLOCK_EXIT_RULES.md)는 커밋 `f66f92f` / PCK `c16e7c1c48d231b437defccbfe4ef7e19bf622f927b7ff28ec455b512a2615e3`에서 실제 실행한 결과다. 두 모드 10판·출구 1,760경로·포커스·8슬롯·안개·저장·경제·복구 결과를 보존한다. 이번 새 PCK에서 그 전체 묶음을 다시 실행했다고 주장하지 않는다.

이번에는 보존된 이전 PCK와 새 PCK를 각각 소스 없는 빈 실행 경로에서 headless로 직접 불러 동일한 독립 추출 하네스를 실행했다. 엔진은 Godot 4.7.2이며 모든 자식 프로세스는 windowsHide:true로 실행했다. 두 실행 모두 오류 없이 종료했다.

| 비교 | 독립 확인 결과 |
|---|---|
| 커밋의 제품 변경 파일 | Rebuild/scripts/board.gd 및 campaign.gd만 변경 |
| PCK 제품 스크립트 14개 | 위 2개만 SHA256 차이, 나머지 12개 동일 |
| board.gd | 5판 이후 하단 12px 띠에 b.capacity를 그리는 3줄을 정확히 1회 제거하면 이전 PCK 원문과 SHA256 동일. 선택·이동·수집 코드는 변경 없음 |
| campaign.gd | LESSONS의 5판 숫자 의미 안내만 바뀌었으며 해당 문구를 이전 문구로 되돌리면 이전 PCK 원문과 SHA256 동일 |
| 10판 정의 | 안내 문구를 제외한 전체 정의 일치. 블록 크기·좌표·색·방향·용량, 경로 제어점, 고양이 지점, 용 수·속도, 안개 값 동일 |
| 10판 초기 상태 | 블록·실·슬롯·용·고양이 위치·총량·속도 모두 동일 |
| 새 PCK 출처 | 내부 제품 스크립트 14개 모두 작업 소스 및 908c8ef 커밋 원문의 SHA256과 일치 |

따라서 이전 전체 검사의 규칙·스테이지·이동 불변식 근거는 이번 표시 변경에도 유지된다. 숫자는 기존 b.capacity를 읽기만 하며 게임 상태를 바꾸지 않는다. 표시 사각형은 기존 블록 몸체 안에 놓인다.

[비교 하네스](capacity_equivalence.gd), [이전 PCK 추출](capacity-before.json), [새 PCK 추출](capacity-after.json), [정확한 해시·출처](CAPACITY_DELTA_PROVENANCE.json)에 근거를 남겼다. 구현 담당의 새 빌드 자체 검사 수치는 본 독립 결과에 합산하지 않았다.

이번 증분 검증은 숫자의 실제 픽셀 가독성이나 Android 기기 동작을 판정하지 않는다. 해당 시각 판단은 별도 시각 리뷰 범위다. 검증 담당은 제품 코드를 수정하지 않았다.
