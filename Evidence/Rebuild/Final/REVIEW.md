# 개편판 0.1 검토 기록

화면 구획과 비율에 대한 사용자 피드백을 반영한 판이다. `previous-layout.png`는 수정 전, `game_00.4s.png`는 수정 후의 실제 화면이다. 파란 상단 무대에 고양이까지 이어지는 길을 드러내고, 네 실패를 가로 선반에 놓아 하단의 크림색 퍼즐 바닥과 구분했다. 보드의 기준 너비를 462에서 564로 늘렸다(화면 너비의 약 64% → 78%). 고양이는 약 21%, 용 머리는 약 13%, 실패는 28% 줄였다. 화면을 가르는 색과 선반, 드러난 경로가 이동 공간과 조작 공간을 다르게 읽게 한다는 것이 이번 시각 검토의 판단이다.

Windows 실행 파일에서 32.07초의 연속 자동 플레이를 녹화했다. 실제 게임의 공개 이동 판정을 사용하며, 색·자리·완료 조건을 우회하지 않는다. 134개 실 단위를 모두 수집하고 피해 없이 클리어했다. 영상은 540×1170, 30fps 고정 녹화이며 실제 성능 벤치마크가 아니다.

191개 규칙 검사와 19개 UI 검사를 통과했다. 세 레벨의 끝까지 이어지는 해법, 실제 뷰포트 탭, 드래그 취소, 길게 누르기, 자리 예약, 일시정지, 소리 설정, 다음 퍼즐과 재도전을 포함한다. 각 레벨의 시작 화면과 진행·성공·실패·일시정지 화면을 직접 확인했다.

변경한 경로의 길이(1396.49)로 세 레벨의 실제 장면 진행을 다시 검사했다. 새 좌표는 보드 입력, 이동 중 블록의 도착점, 실패 렌더링이 공유한다. 고양이에 닿는 마지막 위치도 상단 무대 안에 있다. 432×960과 540×960 윈도우에서도 내부 플레이 뷰포트 캡처에서 보드나 버튼이 잘리지 않는 것을 확인했다. 해당 PNG는 게임 뷰포트 캡처이며 운영체제 창 전체나 모바일 실기기 화면 캡처는 아니다.

화면을 보며 얼굴 방향, 상단 정보 침범, 실패 재질, 머리의 이동량, 실의 출발 위치, 풀리는 조각의 표현, 완료 화면의 시선 분산을 수정했다. 최종 풀림은 원래 실코 크기를 유지하며 행을 소비하고, 같은 경계에서 실패까지 실이 이어진다.

Android는 ARM64 / 최소 API 26 / 대상 API 36이다. 공식 Godot 템플릿의 해시, 앱 이름과 실행 Activity, APK 서명 v2/v3, 16KB 페이지 정렬, 포함된 PCK의 Windows 파일과의 일치를 검사했다. Android 실기기나 에뮬레이터에서 플레이하지는 않았다.

현재 결과는 세 레벨의 플레이 가능한 개편판이다. 반복해서 감는 재미, 장기적인 난이도와 실제 휴대폰의 조작감은 사용자 플레이로 확인할 부분이다. 기술 검사 통과가 사용자 만족을 의미하지는 않는다. 원본 시안은 실제 게임 캡처와 구분해 `Docs/DesignTargets`에 보관했다.

구체적인 검사 로그는 `rules.log`, `ui.log`, `recording.log`, `android-package.log`, `android-signature.log`, `android-alignment.log`에 있다. 전달 파일의 식별값은 `artifacts.json`에 있다.
