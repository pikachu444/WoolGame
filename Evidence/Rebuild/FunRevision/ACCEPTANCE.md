# 선택과 보상 개편 0.4.0

최종 제품 소스: 1eda8383154d1b19431fb3ed0637e8ae6a9d8e86. 정확한 패키지 해시와 크기는 [CANDIDATE.json](CANDIDATE.json)에 기록한다.

## 사용자가 느낄 변경

- 6·8·10판의 실 순서를 출구 검사 순서와 분리했다. 필요한 파랑·주황의 출구를 먼저 열고 선반 한 칸을 남기는 선택을 만들었다. 총 실 수량, 색별 수량, 용별 분배, 속도와 성장 체계는 유지했다.
- 최초 구조 보상이 이름만 다른 그림에서 서로 다른 열 장의 추억 장면으로 바뀌었다. 결과에서 얻은 장면을 크게 보고 수집 화면에 남긴다. 기존 카드 ID와 모드별 소유·저장을 보존한다.
- 독립 검토에서 발견한 잘못된 선반 정체 패배를 수정했다. 실제 수집이 있으면 정체 시간을 초기화한다. 수집이 전혀 없는 실제 정체의 8초 패배 조건은 유지된다.

## 실제 조작과 재미 판단의 한계

[Windows 부분 플레이](Play/native-stage6-review.md)는 정상5판 성장의 격리 프로필로6판을 시작해 실제 클릭으로13% 감김과 파랑 출구 열기를 관찰했다. 보드와 용을 보고 초록을 치워 파랑을 꺼내려는 이유가 읽혔다. 그러나 도구 왕복으로 입력이8–14초 간격이 되어 관찰과 클릭 사이 모달 전환이 생겼고 중단했다. 한 판 수동 완주·정상 사람 속도의 난이도·만회 체감 증거로 쓰지 않는다. 이 부분 관찰은 정체 타이머 수정 전이며 이후 그대로인 시각/출구 읽힘 범위에 한정한다.

보상 캡처는 보상 프로필을 구성한 시각 검사이며 실제 완주 증거가 아니다. 보상 검토 소스와 리소스는 이후 바뀌지 않았고 최종PCK 대조에 포함된다. Android 기기에서의 설치·터치·성능, 사용자가 느끼는 재미와 다음 판을 계속하고 싶은 정도는 미검증이다. 자동 완주와 수치만으로 재미가 입증됐다고 선언하지 않는다.

6판은2.4초 입력에서 전략별 총 완료 시간이 비슷하지만, 필요한 출구를 먼저 열면 감김 공백이 줄었다. 8·10판에서 모든 단순 전략과 계획 전략의 직접 비교는 완료하지 않았다. 자세한 원인·분기·개발 측 관찰은 [FUN_AUDIT.md](../../../Docs/FUN_AUDIT.md)를 따른다.

## 실패와 수정 기록

수정 전 [정체 재현](Rules/stall-after-capture.json)은 마지막 실 수집0.033초 뒤 잘못 패배한 증거다. 수정 전150/160은 최종 균형 판정에서 제외했다. 수정 후에는 같은 선택기가78.6초에 클리어하며, 실제 수집 때 타이머 초기화와 무수집8초 실패를 독립 검사했다. 수정 전·후 자료를 구분해 남긴다.

0.3.0의 증거와 공개 릴리스는 보존했다. 이번 릴리스는 게임 재미를 개선한 테스트판이며 사용자의 실제 플레이 평가를 대체하지 않는다.
