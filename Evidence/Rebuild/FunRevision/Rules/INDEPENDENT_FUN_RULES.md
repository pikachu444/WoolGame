# 재미 개편 독립 규칙 검증

판정: **검사한 규칙·자원 보존과 선택 다양성 범위 통과. 발견한 P1 정체 판정 오류는 수정 확인했다.** 최종 160개 선택 시험 중 158개를 클리어했으며 남은 2개 패배도 아래에 명시한다. 제품 소스는 검증 담당이 수정하지 않았다.

- campaign.gd SHA256: `48a9c2e5beac65486411c1722550fb7ecf505465d8c04f3271d75a0dc48007c4`

- 최종 PCK SHA256: `0b721b0d7e2524991d1801dc73f0680aded35ae1e9619cd82c663f8c96a4245a`

본 독립 검사는 Godot 4.7.2, headless, windowsHide:true로 동결된 **소스**를 실행했다. 실행 결과의 campaign/state 해시가 최종 후보와 일치하며, 두 파일과 보존 대상 4개 파일을 최종 Git 커밋 원문과도 독립 대조했다. 패키지 실행을 본 검증 담당이 했다고 주장하지 않는다. 최종 PCK 리소스·소스 일치 및 APK/Windows ZIP 내부 PCK 일치는 구현 담당의 [패키지 검증 로그](../Verification/pck-source.log), [패키지 무결성 기록](../package-integrity.json), [후보 명세](../CANDIDATE.json)에 연결한다. 독립 실행 명령·파일 해시는 [PROVENANCE.json](PROVENANCE.json)에 기록했다.

## 규칙과 자원 보존

[독립 하네스](independent_fun.gd)의 최종 실행은 741,133개의 반복 확인에서 규칙 실패 0건, 오류 출력 0건으로 종료했다. 확인 횟수는 반복 불변식 비교를 포함하며 독립 시나리오 수가 아니다.

- 10판 전체의 yarn_order가 유효한 블록 ID의 완전한 순열인지 확인했다. 기본 순서는 개발자 witness를 읽지 않고 블록 기하로 독립 재구성했다.
- 생성된 실의 ID·색·용 배정 순서가 정의와 정확히 일치하고, 총량·색별 총량·용별 색 수량이 기준 버전과 같음을 확인했다. 10판 두 용의 색 수량도 보존된다.
- 1~5판·7판·9판은 경로 제어점·블록 배치·크기·색·방향·용량·고양이 지점·용 속도·안개를 포함한 전체 정의가 기준과 같다. 바뀐 6·8·10판도 색별 총량은 같다.
- 매 진행 중 블록의 남은 실과 실제 실 수량, 수집량+잔량, 용별 잔량+수집량, 슬롯·보조 선반 소유권을 확인했다. 이어하기도 세 판의 정확한 실 순서·진행·잔량을 유지했다.
- 최초/반복 보상, 중복 정산 방지, 결과 대기 저장·재로딩, 모드 분리, 성장, 임시 저장 복구를 독립 실행했다. profile/game/board/block_flight의 코드가 기준 버전과 동일함도 확인했다.

결과 원본은 [수정 후 JSON](after-stall-fix.json)과 [실행 로그](after-stall-fix.log)에 있다. 기존 이동 기하·충돌 전체 검사는 변경이 없어 반복하지 않았다.

## 선택의 폭과 느린 판단

선택기는 현재 화면에 노출된 색 수량, 블록의 출구 기하, 이미 선반에 있는 블록의 남은 수요만 사용했다. 숨은 실의 미래 순서, 개발자 choose, hint 또는 witness를 해답으로 읽지 않았다. 두 방식은 ① 가시 수량/블록 용량 비율 우선, ② 현재 감을 수 있는 가시 수량 우선이다. 당장 일치하는 출구가 없으면 가시 색의 앞을 가리는 블록을 독립 기하로 찾는다.

6판은 하트 2·방어, 8·10판은 하트 3·방어·빙결의 정상 성장 상태다. 도구 사용 없이 첫 판단도 2.4초 또는 3.2초 기다린 다음 같은 간격으로 선택했다. 두 방식의 기본 실행과 초기 합법적 블록을 각각 먼저 골라 본 실행을 합해 160개 시험을 수행했다.

| 판 | 판단 간격 | 클리어/시험 | 대체 성공 경로가 있는 첫 선택 | 서로 다른 성공 선택 순서 |
|---|---:|---:|---:|---:|
| 6 | 2.4초 | 26/26 | 12/12 | 24 |
| 6 | 3.2초 | 26/26 | 12/12 | 24 |
| 8 | 2.4초 | 27/28 | 13/13 | 25 |
| 8 | 3.2초 | 28/28 | 13/13 | 26 |
| 10 | 2.4초 | 26/26 | 12/12 | 24 |
| 10 | 3.2초 | 25/26 | 12/12 | 23 |

두 방식의 기본 실행은 모든 판·속도에서 성공했다. 2.4초 판단의 기본 클리어 시간은 6판 60.6~61.0초, 8판 65.1~65.2초, 10판 70.6~78.6초다. 3.2초 판단은 각각 79.8~80.2초, 85.3~85.9초, 91.4~93.0초다. 선택 당시 같은 색의 가시 실이 0개인 블록을 먼저 골라도 만회한 사례가 각 판에 있었다.

모든 합법적 첫 선택에 성공하는 후속 방식이 있으므로 첫 선택 하나를 외워야만 풀리는 구조라는 근거는 없었다. 다만 이것은 모든 중간 분기와 모든 판단 방식의 안전을 증명하지 않는다. 158/160은 정해진 시험 조합의 결과이며 사람의 예상 성공률이 아니다.

남은 2개 패배는 숨기지 않는다. 8판 2.4초에서 ID 2를 먼저 고른 비율 방식은 8/78에서 8초 무수집 선반 정체로 패배했다. 같은 첫 선택의 다른 방식은 성공했다. 10판 3.2초에서 ID 19를 먼저 고른 비율 방식은 93.2초, 103/104에서 마지막 하트가 소진됐다. 같은 첫 선택의 다른 방식은 성공했다. 상세 결과는 [선택 요약](selection-summary.json)에 있다.

## P1 발견과 대표 10판 비교

수정 전에는 실을 실제로 감아도 정체 타이머가 초기화되지 않았다. 10판에서 2.4초마다 ID 19 → 26 → 0 → 13 → 12 → 25 → 18 → 14 → 15를 선택한 뒤, 29.533~30.600초에 5가닥을 더 감고도 30.633초에 정체로 패배했다. 마지막 수집과 패배는 0.033초 차이였다. [수정 전 발견 기록](STALL_TIMER_FINDING.md)

구현 담당이 수집 성공 때 stalled_since를 초기화했다. 같은 최소 재현은 수정 후 40초에 32가닥을 수집하고 계속 진행 중이었다. [수정 전](stall-after-capture.json)과 [수정 후](stall-after-capture-fixed.json)를 별도로 보존했다. 별도 대조 상태에서는 수집이 전혀 없을 때 7.9초까지 살아 있고 8초를 넘으면 정체 패배하는 조건도 유지됐다. 이 대조는 상태를 직접 만든 규칙 경계 검사다.

같은 최대 가시 수량 선택기로 계속 판단하면 수정 전 30.633초의 잘못된 패배가 수정 후 **78.6초 클리어**로 바뀐다. 다른 비율 방식은 **70.6초 클리어**다. 처음 2.4초에 당시 보이지 않는 노란색 ID 1을 먼저 고른 뒤 최대 가시 수량 방식으로 진행한 사례도 **77.2초에 클리어**했다. 이는 패배를 없애기 위해 정해진 정답 순서를 강제한 수정이 아니다. 실제 진행을 정체로 잘못 분류하던 판정을 고친 결과다. 세 선택열의 전체 시각·블록·색·용량·가시 수량은 [10판 비교 JSON](level10-choice-comparison.json)에 남겼다. ID는 검증용 0부터 시작하는 블록 번호다.

## 한계

독립 규칙 검사는 선택 여지와 자원 보존을 확인한다. 화면을 읽는 사람이 실제로 즐겁게 느끼는지, 숫자·색을 알아보기 쉬운지, Android 기기에서 조작감이 좋은지는 headless 결과로 확정하지 않는다. 현재 확인 범위에서 남은 규칙 결함이나 추가 제품 수정 요청은 없다.
