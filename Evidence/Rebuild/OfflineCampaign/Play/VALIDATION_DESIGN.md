# 독립 플레이 검증 설계

상태: 검증 설계 완료, 구현 후보 미수령. 기존 시제품을 새 캠페인의 합격 근거로 사용하지 않는다.

## 기준과 독립성

- 사용자 합의와 Docs/WOOL_CRUSH_RESEARCH_2026-09-10.md를 기준으로 한다. 미확인 원본 수치와 개인용 기본값을 구분한다.
- 먼저 게임 화면과 UI 입력만으로 플레이하며 판단과 막힌 지점을 기록한다. 이후 원본의 대응 장면, 로그, 구현 설명으로 원인을 대조한다.
- 내부 승리 호출, 자동 정답 데모, 저장값 조작으로 성공한 결과를 실제 UI 완주라고 기록하지 않는다. 테스트 계정·저장 경로를 분리해 사용자 진행을 건드리지 않는다.
- 후보 커밋, Windows 패키지 SHA-256, 창 크기, 시작 저장 상태, 입력 방식, 관찰 한계를 각 실행에 기록한다. 제품 소스는 수정하지 않는다.

## 실제 UI 시나리오

| ID | 실행 | 판단 기준 |
|---|---|---|
| P01 | 새 저장에서 홈, 모드 선택, 1판 시작 | 현재 모드·다음 목표·코인·성장 상태를 읽을 수 있다. 시작 구도는 0% 원본과 비교한다. |
| P02 | 색과 방향을 보고 직접 선택; 막힌 블록과 연속 클릭 포함 | 클릭 대상·막힌 이유·이동 슬롯이 보인다. 중복 입력으로 물체가 사라지거나 슬롯이 겹치지 않는다. |
| P03 | 한 가닥 및 여러 가닥 수집을 추적 | 블록→가로 실감개→용 접점→감김 수량→빈자리의 인과가 읽힌다. 접점·완료 효과가 위협을 가리지 않는다. |
| P04 | 일부러 기다려 첫 도주, 마지막 위치 공격, 실패 관찰 | 도주 전에 위협이 있고 이동 경로가 납득된다. 도주와 피해가 구분된다. 멀리서 갑작스런 하트 차감이나 일반 피격 격퇴가 없다. |
| P05 | 실패 후 무료 재도전, 이어하기, 코인 부족 상황 | 버튼의 비용·복구 결과를 예측할 수 있다. 재도전은 초기판, 이어하기는 같은 진행으로 돌아오고 남은 실을 다시 고를 수 있다. |
| P06 | 슬롯 포화에서 도구 사용; 안개·화면 밖 강화와 종료 경험 | 어떤 문제가 해결됐는지 보이고 소모가 중복되지 않는다. 강화 종료 후 상태가 설명 없이 이상해지지 않는다. |
| P07 | 직접 선택으로 10판의 시작·중간·위기·마무리 경험 | 실제 선택 차이가 생긴다. 색만 바꾼 반복, 화면 밖 클릭, 판독 불가능한 방향, 해결 불능 상태를 찾는다. |
| P08 | 방어 능력 해금 전후 및 복수 용 플레이 | 방어·동결·격퇴가 서로 구별되고 어느 용이 위험한지 읽힌다. 효과 중 하트 변화가 납득된다. |
| P09 | 클리어→결과·보상→홈→다음 판; 결과에서 즉시 종료 후 재실행 | 무엇을 구하고 얻었는지 보인다. 코인·카드·해금이 한 번만 보존되고 다음 행동이 명확하다. |
| P10 | 도전과 자유를 오가며 도구·이어하기·카드·코인 확인 | 무료 표시와 비용 표시가 일관되고 서로의 기록이 섞이지 않는다. |
| P11 | 10판 완료 후 홈, 수집 보기, 이전 판 재플레이, 재실행 | 캠페인 끝이 세 판 순환처럼 보이지 않는다. 완료 기록·성장·카드와 재플레이 진입이 남는다. |
| P12 | 기본 창과 작은 세로 창에서 UI 관찰 | 위 경로/중간 선반/아래 보드가 구분된다. 해제 글자가 + 영역 제외 중앙에 있고 작은 화면에서도 버튼·숫자를 읽고 누를 수 있다. |

도전 모드에서 10판 흐름을 기본으로 검증하고 자유 모드는 별도 새 저장에서 무료 도구·이어하기·보상·저장과 모드 전환을 확인한다. 규칙 검증의 자동 10판 해법은 이 직접 플레이와 별도 증거다.

## 정성 판정

- 첫 선택: 무엇을 누를 수 있고 왜 막혔는지 설명 없이 이해되는가.
- 수집: 어느 색이 풀려 어디에 감겼는지 움직이는 동안 추적되는가.
- 위기: 고양이를 구해야 한다는 긴장이 생기는가. 위험을 보고 대응할 여유가 있는가.
- 실패: 이유와 복구 선택이 납득되는가. 억울함이나 진행 유실 느낌이 남는가.
- 성공: 실제 구조를 끝냈다는 느낌과 보상이 연결되는가.
- 다음 판: 다른 판단을 요구하는가. 성장·카드가 계속할 이유로 보이는가.

각 항목은 충족/부분 충족/미충족과 관찰 문장으로 판정한다. 미관 점수 평균으로 막히는 문제를 감추지 않는다. 에이전트의 정성 판단은 실제 사용자 평가를 대신한다고 주장하지 않는다.

## 증거와 수정 검증

각 지적에 후보 해시, 모드·판·시점, 실행 입력, 예상/관찰, 스크린샷 또는 녹화 타임코드, 영향, 재현 여부를 남긴다. 진행 불가·저장 유실·설명되지 않는 피해·주요 수집 추적 실패는 전달 차단 사유다. 구현 담당 수정 후 해당 경로와 인접 정상 경로를 재검증한다. 후보가 바뀌면 판정의 적용 해시를 갱신한다. Windows 입력/화면 검증과 Android 패키지 검사를 구분하며, Android 실제 기기를 쓰지 못하면 명시한다.
