# 독립 규칙 검증 — 오프라인 10판 캠페인

판정: **검사한 규칙 범위 통과**. 후보 커밋 `114e7f3e8e21b3dc072277b1ecc6266bd24790a9`의 최종 PCK를 다시 검사했고, 미해결 규칙 실패는 없다. 실제 UI 플레이 완료 판정은 별도다. 제품 코드를 수정하지 않은 규칙 검증 담당이 작성했다. 구현 담당의 테스트와 별도로 상태·방향·보이는 실을 읽는 하네스를 사용했다.

## 검증 방식

- 구현의 `witness` 또는 `request_hint()`를 해법으로 사용하지 않았다. 블록 위치·크기·방향으로 출구를 검사하고, 화면에 노출된 실, 이미 슬롯에서 감는 잔량, 필요한 선행 블록을 판단해 `select()`만 호출했다.
- 시뮬레이션 시간을 진행하는 headless 규칙 검사다. 마우스·터치로 실행 화면을 조작한 플레이 검증으로 제시하지 않는다.
- 원본 영상에서 확인된 행동 구분과 승인된 개인용 수치를 검사한다. 원본의 미확인 HP 판정·부활 수치까지 같다는 인증이 아니다.

## 확인한 범위

| 범위 | 확인 내용 |
|---|---|
| 신규 판의 해결 가능성 | 두 모드에서 각각 1~10판, 도구 없이 정상 선택으로 완료 |
| 실제 게임 연결 | game.tscn에서 모드별 10판을 순차 진행, 승리 콜백 즉시 보상 저장, 새 Profile로 재로드, 홈 복귀·다음 판·재플레이 |
| 도주·공격 | 두 도주 지점 통과와 하트 보존, 마지막 지점 공격 예고·화염·피해, 일반 피해와 별도 격퇴 구분 |
| 능력·복수 용 | 무적·동결 판당 한 번, 무적 뒤 격퇴, 복수 용의 동시 공격 보호, 정지·재개 |
| 실·슬롯 | 색별 잔여 실/용량 보존, 이동 중 슬롯 예약, 중복 입력 거절, 완료 슬롯 반환, 보조 선반 잔량 |
| 도구·비용 | 잔액 부족·일시정지·승리 후 거절 시 비용 없음, 모드별 비용, 강화 중 화면 밖 수집과 종료 후 제한 복귀 |
| 이어하기 | 작업 중 실패를 주입한 20개 경계 상태와 자연 피격으로 실패한 10판을 별도로 검사. 진행·남은 실 보존 및 정상 입력 해법 확인 |
| 영속 진행 | 첫 보상50/재보상20, 카드10장·중복 방지, 성장 해금 재로드, 모드별 코인·수집·성장 분리 |
| 저장 복구 | 정상 파일·더 최신의 완료된 tmp·잘린 tmp를 비교, 중복 결산·재접속 보상·저장 불가 오류 확인 |
| 시간 경계 | 60fps/30fps 분할 진행에서 공격 보호와 최종 결과 확인. 공격 경계의 한두 프레임 차이를 정확한 동일 시점 상태로 오판하지 않음 |

반복 불변식 확인 횟수는 독립 시나리오 수가 아니다. 성공 경로가 있다는 결과는 모든 무작위 선택이 성공한다는 뜻이 아니다.

## 발견과 수정 재검증

1. **저장 후 완료 레벨의 숫자 타입이 바뀌는 결함**을 재현했다. 재접속 후 성장 효과가 사라지고 같은 판이 첫 클리어로 취급돼 50코인과 카드가 중복됐다. 구현 담당이 정수 정규화를 적용했고 같은 재현 경로와 실제 씬 통합 검사에서 수정 확인했다.
2. **10판 이어하기의 입력 여유가 좁았다.** 최초280px 후퇴에서는 선택 간격0.25초 해법만 성공한 변형 묶음이 있었다. 후퇴·접근 간격 조정 뒤 최종 `max(720, speed*45)`에서는 단순 선택기의 0.25/0.4/0.6/0.85/1.35초 간격이 모두 성공했다. 단순 선택기의 0.1초 연타 실패와 작업 중 복구의 일부 슬롯 막힘도 숨기지 않고 보존했다. 이미 슬롯에서 감는 실 수요를 빼는 독립 선택 전략으로 보완한 뒤에는 최종 PCK의 0.1/0.25/0.4/0.6/0.85/1.35초 해법이 모두 성공했다. 선택기 보완은 제품 코드 변경이 아니며, 모든 임의 선택이 성공한다는 뜻도 아니다.
3. 손상 tmp를 의도적으로 넣었을 때 복구는 됐지만 오류 로그가 발생했다. 반환값을 검사하는 JSON 파서로 변경 후 예상 손상 복구에서 불필요한 엔진 오류 로그가 없어졌다.

## 최종 후보 재검증

- 커밋: `114e7f3e8e21b3dc072277b1ecc6266bd24790a9`
- PCK SHA-256: `685155149327a4d061b6d8a1f03be065332208804ae5513acbe3c7c9a7f9c56e`
- 검사 런타임: Godot4.7.2의 console 실행기. `--main-pack`으로 최종 PCK를 로드했다. 배포 릴리스 실행기는 외부 경로를 지정하는 하네스 옵션을 금지하므로, 배포 EXE에서 같은 외부 하네스를 실행했다고 주장하지 않는다.
- PCK 안의 state/profile/campaign/game 네 스크립트 SHA-256을 후보 커밋의 Git blob과 각각 대조했고 모두 일치했다. [검증 대상과 명령](PROVENANCE.json)
- 규칙 검사: 반복 불변식 확인80,773회, 고유 실패0. 씬 통합: 반복 확인30,774회, 고유 실패0. 두 최종 로그에 엔진 오류나 경고가 없다.
- 10판 자연 실패 후 복구: 선택 간격0.1/0.25/0.4/0.6/0.85초는 약43.1초, 1.35초는 약45.1초에 성공했다. [재현 입력 전체](package-recovery-variants.json)

첫 패키지 검사에서 발생한 씬 종료 경고는 하네스가 재생 중인 AudioStreamWAV를 즉시 종료하면서 남긴 것이었다. 검증 종료 시 오디오를 정지하고 짧게 정리한 뒤 같은 검사에서 경고가 없어졌다. 제품 소스를 수정하지 않았다. [대상 확인 로그](package-scene-verbose.log)

재실행할 때는 세 하네스를 `BuildWork/IndependentRules`에 복사하고 그 아래 `profile` 폴더를 만든 뒤 PROVENANCE의 명령을 사용한다. 씬 통합의 `--profile-dir`는 매 실행마다 새 격리 디렉터리를 지정한다. 하네스의 기본 경로는 이 작업 공간이며 다른 체크아웃에서는 `out`, `workspace`를 해당 위치로 바꾼다.

**남은 사용자 검증:** Windows 실제 입력 플레이와 Android 기기 플레이. 이 보고서의 통과로 이 두 항목을 완료 처리하지 않는다.
