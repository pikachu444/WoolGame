# 털실 구조대 · 원본 화면 재현 개편

Godot 4.7.2 / GDScript의 고정 시점 게임이다. 현재 사용자 논의를 기준으로 기존 Unity와 별도로 제작했다. Windows 실행 파일은 ../Builds/Rebuild/WoolRescue.exe이며 같은 폴더의 PCK가 필요하다. 검토 기록·실행 영상은 ../Evidence/Rebuild/ReferenceMatch에 있다. 이전 Final 폴더는 이번 사용자가 지적한 수정 전 결과다.

## 재현한 범위

V04 원본 동영상을 직접 내려받아 프레임을 확인했다. 광고와 OS 영역을 제외한 게임 화면은 592×1138이며 무대 y0–420, 실패 작업대 y421–552, 블록 영역 y553–1037, 도구 y1038–1137이다. 그 좌표에 맞춰 첫 장면의 9개 블록, 가로 실패 4개, 추가 자리, 고양이·용과 도구를 배치했다.

영상은 이미 76% 진행된 후반 퍼즐이다. 첫 퍼즐은 그 관찰 상태(수집 181/238, 남은 블록 9개와 감기 중 실패 3개)를 복원한다. 원본 레벨 전체를 역설계했다는 뜻은 아니다. 뒤의 두 퍼즐은 같은 화면 구조에서 만든 자체 배치다. 풀림·감김·속도·도구 효과의 세부 규칙도 관찰을 바탕으로 구현한 것이며 원본 내부 코드와 동일하다는 주장은 하지 않는다.

## 수정 지점

- scripts/layout.gd: 원본 게임 화면의 공통 좌표.
- scripts/levels.gd: 관찰한 9블록 배치와 두 자체 밀집 배치.
- scripts/state.gd: 방향 장애물, 자리 예약, 수집, 도구, 피해와 완료 판정.
- scripts/world.gd / spool.gd: 몸통 겹침, 캐릭터, 풀림과 수평 감김.
- scripts/board.gd: 블록 표시와 실제 탭·드래그 입력.
- scripts/hud.gd: 설정, 네 도구, 해제, 성공·실패·일시정지 화면.
- art/PROVENANCE.md: 생성 자산과 글꼴 출처.

## 빌드와 확인

저장소 루트에서 python Rebuild/tools/build.py --android 를 실행한다. 로컬 Tools/Godot의 4.7.2 실행 파일·공식 템플릿, Apktool 3.0.3, Android SDK 36/JDK를 사용한다. 편집기 시작 지연 때문에 리소스와 PCK는 Godot 런타임 API로 생성한다.

빌드는 규칙 및 실제 뷰포트 입력 검사 후 Windows 패키지와 ARM64 APK를 만든다. APK는 공식 Godot 템플릿에 같은 PCK를 넣으며 실행 진입점, 서명, 16KB 정렬과 내장 PCK 일치를 확인한다. Android 실기기 플레이는 확인하지 않았다.

실행 파일에 --write-movie <절대경로.avi> --fixed-fps 30 -- --demo --level 0 --quit-after 32 를 주면 정상 판정 API를 사용하는 자동 시연을 녹화한다. 고정 프레임 녹화는 실시간 성능 측정이 아니다.

최종 품질은 독립 검토 기록의 범위로만 해석해야 한다. 영역 구성이 맞아도 원본과 그림·움직임이 완전히 같다는 뜻은 아니다.
