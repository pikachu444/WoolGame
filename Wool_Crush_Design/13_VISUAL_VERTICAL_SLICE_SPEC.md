# Visual Vertical Slice — 완성 기준

2026-09-08. 첫 구현용 **우리 게임의 설계 결정**. 원작의 기기 성능·shader 파라미터를 측정한 값이 아니다. 아직 Unity 프로젝트나 APK를 만들지 않았다.

## 목적과 범위

**털실 마스터 화면과 나란히 놓았을 때 뜨개 재질·통통한 형태·감김 동작이 크게 초라하지 않은 한 장면**을 먼저 성공시킨다. 수십 레벨이나 solver보다 먼저 검증한다. 09A를 실행 지시문으로 사용한다.

WoolLab scene 하나에 배경/조명/고정 카메라/독자 솜구름 용/크림 고양이/네 작업 자리/방향 블록 네 개/24 yarn unit/짧은 구조 성공을 만든다. 블록 용량은 4·4·6·10, 네 색의 총 공급과 정확히 일치한다. 이것은 시연 데이터이며 원작 레벨 복제본이 아니다. 시각 비교는 실제 실행 캡처로 한다.

## What must look similar to Wool Crush (털실 마스터)

**이번에 사용자가 확정한 비교 대상은 털실 마스터 / Wool Crush**다. 이전 Wool Master 3D package는 비교 자료에서 제외한다.

- 위쪽의 긴 귀여운 뜨개 생물, 가운데 실타래, 아래쪽 색 블록이라는 높은 가독성의 세로 구도.
- 두께 있고 겹치는 편물 마디, 촘촘한 V 조직, 밝은 실색과 부드러운 접촉 그림자.
- 블록은 즉각 반응하고 화살표 방향으로 탈출한 뒤 같은 색 실타래가 된다.
- 풀리는 지점·이동하는 연결 실·목적지 감김이 하나의 연속 동작으로 느껴짐.
- 카메라를 돌리지 않아도 색·막힘·자리 여유가 읽힘.
- 완료할 때 마디가 매끄럽게 정리되고 귀여운 구조 반응을 보여줌.

## What must intentionally be different

- 얼굴, 뿔/귀, 마디 끝 모양, 고양이 무늬, 배경 소품, UI 도형과 소리는 독자 제작.
- 원작의 광고·VIP·Unlock 과금·재화·로그인 UI는 없음.
- 기본 생각 모드와 무료 pause/undo를 제품 단계에서 제공. 시각 씬은 pause와 다시 보기만으로 충분.
- 공격적인 표정·불로 동물을 괴롭히는 반복 연출 대신 순한 위기/구조 표현.
- 동일 원작 보드 배치와 레벨 데이터를 옮기지 않음.
- 플레이용 touch drag rotation은 구현하지 않음. 대상 정정으로 이전 요구를 철회한 것이다. Editor의 아트 조정용 orbit만 허용.

## 장면·아트 수용 기준

B는 마디 폭 1, 화면 검사는 안전 영역 기준. 시작값은 아트 비교 후 바꿀 수 있으나 변경 기록을 남긴다.

| 항목 | 시작값 / 통과 조건 |
|---|---|
| 화면 | Portrait, 19.5:9 기본. 16:9·20:9에서도 핵심 UI 잘림 없음 |
| 화면 배분 | 상단 35%±3, 작업대 10%±2, 보드 44%±4, 도구 11%±2 |
| 생물 framing | 상단 영역 폭의 85–95% 안에서 경로가 읽힘. 머리/고양이가 작업대 숫자를 가리지 않음 |
| 카메라 | orthographic 시작, 보드 법선 대비 기울임 15–25°. gameplay orbit 없음 |
| 마디 실루엣 | 길이 .55–.75B, 두께 .25–.40B, 간격 .40–.55B. 기본값 길이 .65B/간격 .45B |
| 둥글림 | radius .08–.15B. 종이처럼 얇은 끝/각진 저폴리 외곽이 기본 거리에서 보이지 않음 |
| 몸통 mesh | 마디당 400–900 triangles, 24 unit부터. 전체 예산을 우선 |
| knit 조직 | B당 12–20 stitch 열. 무늬가 흐르는 방향이 마디에 고정되고 코너에서도 늘어나지 않음 |
| normal/AO | 자체 제작 조직. relief 느낌 .003–.008B부터. AO가 활성 색을 검정으로 만들지 않음 |
| material | opaque, metallic 0, smoothness .18 시작. 낮은 specular, 약한 grazing fuzz |
| fuzz | 기본 거리 외곽 약 1px의 부드러운 느낌. 빛나는 플라스틱 rim이나 두꺼운 halo 금지 |
| 연결 실 | 지름 .035–.060B. 단면 8/LOD6, 샘플 .08B부터 곡률 적응. chord error 목표 .5px |
| 연결 최대량 | 동시에 4개. 합계 8k triangles 이하. 교차하더라도 색/목적지 읽힘 |
| 조명 | 주광 1+밝은 ambient. 블록 바닥·마디 겹침에 soft contact shadow |
| renderer | URP Forward, Linear, HDR off, MSAA2×, shadow atlas1024 출발/최대2048 |
| 후처리 | Bloom·DOF·motion blur·SSAO 기본 off. 켤 경우 비교와 비용 기록 |
| 고양이 | 머리 높이/전체 약 .50, 눈 폭/얼굴 .17, 눈 중심 간격/얼굴 .44 시작 |
| 색 | 03의 독자 palette. 몸통/블록/실타래의 색 ID가 조명 차이에도 같은 색으로 읽힘 |

normal/tangent의 실제 섬유 표면 구현은 04를 따른다. 원작과 같은 품질의 판단을 geometry 숫자만으로 통과시키지 않는다.

## 입력·애니메이션 수용 기준

| 사건 | 시간/행동 | 실패 예 |
|---|---|---|
| Tap | pointer-down 후 80ms 내 시각 반응. tap 후보 이동 허용량 8dp, release≤350ms 시작 | 반응 없이 나중에 갑자기 이동 |
| 터치 크기 | 가능한 target 48dp 이상. 작은 블록은 시각 크기와 별도 hit 영역 조정 | 겹친 hit 영역이 항상 같은 블록만 선택 |
| 선택 highlight | scale/밝기 변화 80–120ms, 이웃을 과하게 가리지 않음 | 얇은 흰 선만 보여 선택이 안 읽힘 |
| 블록 탈출 | 총 250–400ms. 먼저 화살표 방향으로 보드 밖으로 나온 뒤 작업대 곡선 경로 | 다른 블록을 관통하며 곧장 슬롯으로 순간 이동 |
| 슬롯 도착 | 80–140ms 착지 압축. 중심 오차 2px 이하 | 해상도 바뀌면 선/실타래 어긋남 |
| 풀림 준비 | pull point로 100–180ms 수축 | 덩어리 전체 알파만 줄어듦 |
| 수집 표현 | 180–350ms에 마디 잔여 조직 감소와 연결 선·코일 증가 | 원천과 목적지의 변화가 따로 놂 |
| 실 반응 | 가벼운 곡률/긴장 변화. 큰 밧줄 출렁임 없음 | 고무 호스나 물줄기처럼 보임 |
| 자리 완료 | 120–220ms 팝/작은 흰 섬유 효과, 다음 상태가 명확 | 과한 particle이 남은 수용량을 가림 |
| 몸통 정리 | 100–180ms 간격 회복, 코너 마디 끊김 없음 | 삭제 구멍·teleport가 보임 |
| 성공 | 800–1400ms 눈웃음/앞발 인사/순한 퇴장, 재생성 가능 | 승리 텍스트만 나타남 |
| Pause | 움직임/수집/효과 정지·재개 일관성 | 복귀 순간 체인 건너뛰기 |

동시 수집이 애니메이션보다 빠르면 같은 원천/목적지의 표현을 집계할 수 있다. 이후 Core 통합 시 **논리 tick과 표현 지속시간은 분리**한다. callback을 기다려서 논리 수집을 미루지 않는다. 데모에는 단계별 느리게 보기와 재생 속도 0.5/1.0을 두어 끊김을 찾는다. 이는 디버그 UI다.

## Android 성능 게이트

모두 목표값이다. 실제 측정 전 ‘60fps 달성’이라고 보고하지 않는다. 중급 목표군은 Android 6GB RAM, Snapdragon695/Adreno619 또는 Mali-G68급. 낮은 사양은 30fps 프로파일을 별도 검증한다. 기기명·OS·render resolution·build type·온도 조건을 기록한다.

| 지표 | 목표 / 허용 상한 |
|---|---|
| 중급 FPS | 60fps 목표. 15분 반복 후 frame time p95≤20ms, p99≤33.3ms |
| 저사양 FPS | 30fps 목표. p95≤36ms, p99≤50ms |
| CPU/GPU | 중급에서 각각 대표 부하 구간 16.7ms 안을 목표. bottleneck을 따로 기록 |
| 화면 triangles | 목표≤60k, 상한100k. shadow pass 수치는 별도 기록 |
| render batches | 목표≤60, 상한100. instancing/SRP Batcher가 실제 몇 draw를 줄였는지 확인 |
| texture GPU memory | 목표≤32MiB, 상한64MiB, ASTC+mip 기본 |
| steady GC | 프레임당 0B 목표. 지속 할당/주기적 큰 수집 없음 |
| total process memory | 목표≤350MiB, 상한500MiB. 측정 도구 기준 명시 |
| 불필요한 overdraw | 전신 alpha fur 없음. 동시 효과4개 상황 확인 |
| 안정성 | 15분 반복·앱 전환10회·다시 보기20회에서 crash/상태 누적 없음 |

Editor 수치를 Android 값으로 제출하지 않는다. 실제 기기가 없으면 데스크톱 시각 기준까지만 통과로 표시한다. 처음부터 최적화 목표를 못 맞추면 미세 섬유/그림자 비용부터 조정하고 큰 실루엣·뜨개 조직은 유지한다.

## 비교 판정 방법

1. U1/V4 실제 화면과 우리 캡처를 같은 세로 비율·화면 크기로 놓는다. 광고 제외 영역이 다르면 표시한다.
2. 전체 화면, 마디/블록 확대, 풀림 중간, 성공의 네 장면을 제출한다. 원작 캡처는 SOURCE, 우리 실행은 OUR PROTOTYPE라고 표기한다.
3. 정지 화면만이 아니라 10–20초 실제 실행 영상으로 연결감·조직 흔들림·숫자 가독성을 본다.
4. 아래 항목을 0–2로 평가한다. 0=명백히 미달, 1=차이가 있지만 읽힘, 2=같은 장르의 완성된 화면처럼 보임. 이것은 수학적 유사도나 외부 사용자 시험 결과가 아니다.

| 항목 | 2점의 관찰 기준 |
|---|---|
| 실루엣 | 둥근 겹침과 머리/몸통 비율이 기본 거리에서 귀여움 |
| 뜨개 재질 | V 조직·폭신함이 읽히고 고무/플라스틱 느낌이 약함 |
| 색·명암 | 원작 정도로 선명하면서 골/그림자가 색 구분을 해치지 않음 |
| 구도·가독성 | 위 진행·중간 자리·아래 선택이 한눈에 읽힘 |
| 촉각적 연결 | source→실→spool 동작이 끊기지 않고 만족스러움 |
| 성공 매력 | 한 번 더 보고 싶은 표정/작은 동작이 있음 |

**아트 통과 기준:** 12점 중 10점 이상을 목표로 하고, 뜨개 재질/촉각적 연결은 각각 2점, 다른 항목에 0점 없음. 만든 사람이 체크한 잠정 평가임을 표시한다. 이후 아내가 실제 기기에서 비교했을 때 ‘원하는 털실 분위기’로 느끼는지가 최종 수용 기준이다. 지금 자료 제공을 요구하는 단계는 아니다.

**전체 통과:** 아트 게이트 + Android 성능 게이트 + 4블록 시연의 입력/수집/성공 반복 동작. 어느 하나 미달이면 GameplayLab 확장보다 해당 항목을 먼저 수정한다.

## 산출과 후속 작업

Unity 프로젝트·독자 ArtSource·재생성 명령·버전 lock·APK·실측표·4개 실제 캡처·10–20초 영상·미통과 항목을 제출한다. solver/generator/24레벨은 만들지 않는다. 데모가 통과한 뒤 09B에서 순수 Core와 수동 level/solver를 구현하고, 그다음 이 씬에 연결한다.
