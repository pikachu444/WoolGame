# 우리 게임 플레이 규칙과 상태 전이

사양: Candidate Ruleset `cozy-orders-v1` · 2026-09-08

이 문서는 구현 가능한 **독자 게임 후보 규칙**이다. 원작과 일치함이 확정된 규칙표가 아니다. 원작의 매치 수·blocking·실패 순서는 01의 E1~E3 검증 후 비교하고, 차이가 크면 대량 콘텐츠 제작 전에 수정한다. 광고 제거·오프라인·무료 복구 원칙은 확정이다.

## 1. 한 레벨의 경험

귀여운 3D 털실 조형을 돌려 보며 풀 수 있는 묶음을 탭한다. 같은 색 수집대가 열려 있으면 그쪽으로 실이 감기고, 없으면 보관대에 실뭉치로 놓인다. 수집대가 3단위로 채워지면 그림의 한 구역이 완성되고 다음 색 수집대가 열린다. 바깥 묶음을 치우면 아래 묶음이 드러난다. 전체 실을 수집하면 그림을 완성하고 조형을 도감에서 감상할 수 있다.

해체 대상은 3D 조형이고, 완성 보상은 작은 털실 그림이다. 도감에는 **초기 조형의 완전한 모습**을 별도 감상용 복원 상태로 저장한다. 마지막에 원래 조형이 저절로 남는다는 규칙은 없다. 그림은 같은 3D 모델의 정면/3분면 렌더를 작은 구역으로 나눈 표현으로 제작해 콘텐츠 비용을 줄인다.

## 2. 규칙 상수

| 항목 | 표준 모드 | 편안하게 모드 |
|---|---|---|
| 활성 수집대 | 2개 | 3개 |
| 수집대 1개의 요구량 | 같은 ColorId 3단위 | 동일 |
| 임시 보관칸 | 5개 | 7개 |
| 실 묶음 1개 | 논리적으로 정확히 1단위 | 동일 |
| 제한 시간·에너지 | 없음 | 없음 |
| 되돌리기 | 레벨 내 제한 없음 | 제한 없음 |
| 힌트 | 레벨당 3회, 시간 비용 없음 | 제한 없음 |
| 긴급 정리/실 삭제 | 기본 모드에서 없음 | 별도 자동 진행은 후속 범위 |
| 진행 중 난이도 변경 | 재시작 없이 편안하게로 완화 가능 | 표준 복귀는 다음 레벨/재시작 |

모든 레벨의 필수 해답 검증은 **표준 2/5/3**으로 한다. 편안하게 모드로 풀렸다는 이유로 표준 모드에 레벨을 등록하지 않는다. 도움 사용을 실패로 표시하거나 수집 보상을 줄이지 않는다.

수집대는 “현재 요구색이 정해진 주문”이고, 보관칸은 “어떤 색이든 1묶음을 잠깐 놓는 자리”다. 보관대에 같은 색 3개가 있어도 그 색 주문이 활성화되지 않으면 없어지지 않는다. 숫자가 3이라는 이유로 자유형 트리플매치 규칙을 섞지 않는다.

## 3. 데이터와 상태

| 개념 | 값과 책임 |
|---|---|
| YarnPiece | 고유 id, ColorId, blockerIds, ownerGroupId; 논리 1단위 |
| PieceLocation | Board / Buffer(index) / Order(orderId) / Consumed |
| Layer | 제작용 시각 분류. 제거 판정은 Layer 번호가 아닌 blockerIds로 결정 |
| SupportGroup | 소유한 실이 모두 Board를 떠나면 제거된 것으로 파생. 의존관계는 제작 시 piece blockers로 컴파일 |
| ActiveOrder | orderId, colorId, collectedPieceIds, capacity=3 |
| OrderQueue | 레벨 생성 때 확정한 유한한 순서. seed와 함께 저장 |
| Buffer | 0~B-1의 빈칸 또는 pieceId. 들어간 순서를 보존 |
| ArtworkState | 완료된 orderId 집합. 표시 면적/색상 마스크는 별도 데이터 |
| LevelPhase | Loading / Ready / Resolving / Blocked / Won / Paused; 논리 결과와 Session의 재생 phase는 구현에서 분리 |
| LevelState | 위 값 + moveIndex + rulesetVersion + levelHash |
| UndoSnapshot | 마지막 정상 입력 전의 전체 논리 상태. 카메라는 별도 UX 상태 |

현재 화면 가림과 논리적 차단을 분리한다. `LogicallySelectable(p)`는 p가 Board에 있고 모든 blocker가 Board에서 제거됐는지로 결정한다. `CanHit(p,camera)`는 UI가 아닌 영역에서 보이는 p를 실제로 터치했는지다. 정상 탭은 두 조건을 모두 만족해야 한다. 회전/확대로 제거 규칙 자체는 바뀌지 않는다.

Layer나 SupportGroup을 두 번째 가변 상태로 중복 보관하지 않는다. 그룹 소유 조각들이 Board를 떠났는지에서 파생하므로 undo 때 불일치가 생기지 않는다.

## 4. 한 번의 선택을 처리하는 정확한 순서

1. `Ready` 또는 `Blocked`에서 입력한다. `Blocked`에서는 undo·완화·restart만 가능하다.
2. UI hit, 드래그로 판정된 입력, 동일 조각 중복 탭을 먼저 걸러낸다.
3. Board 존재 여부와 blocker를 확인한다. 막힌 조각이면 상태 변경 없이 이유를 짧은 테두리 표시로 알려 준다.
4. 같은 ColorId의 빈 공간 있는 활성 주문을 찾는다. 둘 이상이면 화면의 수집대 인덱스가 작은 곳을 우선한다.
5. 없으면 Buffer의 가장 작은 빈 인덱스를 예약한다. 보관이 꽉 찼어도 같은 색 주문으로 직접 보낼 수 있으면 허용한다.
6. 어느 곳에도 보낼 수 없으면 입력을 거부한다. **여섯 번째 실을 이미 지운 뒤 패배시키지 않는다.**
7. 입력 전 상태를 undo에 저장하고, 한 번의 논리 트랜잭션 안에서 Board → 목적지 이동을 반영한다. 이 시점부터 제거된 조각은 blocker가 아니다.
8. 수집대가 3개로 차면 세 piece를 Consumed로 바꾸고 해당 order를 완료한다. 그림 구역을 완료 집합에 추가한다.
9. 비워진 수집대에는 OrderQueue의 다음 주문을 넣는다. 동시에 둘이 비면 낮은 인덱스부터 채운다. 큐가 끝나면 그 수집대는 비활성화한다.
10. Buffer를 오래 들어온 순서로 스캔하여 매칭 가능한 첫 piece를 가장 낮은 인덱스의 맞는 주문으로 옮긴다. 완료·주문 교체를 처리한 다음 스캔을 처음부터 반복한다. 빈칸은 이동 완료마다 왼쪽으로 압축한다.
11. 더 이상 자동 변화가 없을 때 승리와 막힘을 판정한다. 이벤트 목록과 논리 결과를 원자적으로 저장한다.
12. Presentation이 이벤트를 재생하는 동안 `Resolving`으로 보인다. 판정과 난수 선택은 애니메이션 callback에 넣지 않는다. 재생 완료 후 최종 Ready/Blocked/Won 표시로 전환한다.

논리 상태 계산은 즉시 끝나지만 장면은 순서대로 따라간다. MVP에서는 동시 선택 1개만 허용한다. 회전은 허용하되 다음 선택은 animation settle 뒤 받는다. 나중에 입력 예약을 넣더라도 목적지 예약과 revision 검사를 통과한 요청만 수용한다.

## 5. 전이표

| 현재 | 사건 | 조건 | 다음 / 효과 |
|---|---|---|---|
| Loading | Load | 데이터·해시·인증서 유효 | 정규화 후 Ready |
| Ready | Tap(p) | blocked 또는 보낼 곳 없음 | Ready, 변경 없음 |
| Ready | Tap(p) | 유효 | Resolving, 이동 트랜잭션 |
| Resolving | AnimationSettled | 남은 유효 move 있음 | Ready |
| Resolving | AnimationSettled | 모든 piece 수집됨 | Won |
| Resolving | AnimationSettled | 미완료이고 유효 move 없음 | Blocked |
| Ready/Blocked/Won | Undo | 히스토리 있음, Next 이전 | 이전 snapshot 복원 후 Ready/Blocked 재계산 |
| Resolving | Undo | 히스토리 있음 | 이벤트 취소, 현재 revision 폐기, 이전 snapshot 복원 |
| Ready/Blocked | Restart | 사용자 선택 | 같은 levelHash·큐·색·배치의 최초 상태 |
| Ready/Blocked | Relax | 완화 모드 선택 | 변경 전 모드 포함 snapshot 저장, B=7·수집대=3 확장, 큐의 다음 주문을 새 슬롯에 열고 자동 정규화 |
| 임의 플레이 상태 | 앱 background | 항상 | 저장된 논리 결과 유지, 소리/진동 중지 |
| Paused | Resume | 데이터 유효 | 저장 snapshot 기준 시각 복구; 이동을 다시 계산하지 않음 |
| Won | Next | 다음 콘텐츠 있음 | 다음 레벨 Loading |

완료 애니메이션 도중 undo를 누를 수 있다. Next로 넘어가기 전까지 현재 레벨 snapshot을 유지한다. 수집 보상 기록은 `(levelId, contentRevision)`에 대해 멱등 처리한다.

Relax도 하나의 undo 가능한 명령이다. 이를 되돌리면 이전 모드·용량·활성 주문·큐·보관이 함께 복원된다. 완화가 이미 만들어진 모든 깊은 deadlock을 반드시 해결한다고 보장하지 않는다. 필요하면 더 앞선 선택으로 무료 undo한다. 보상을 이미 받은 레벨에서 undo해도 도감을 빼앗지 않으며, 재완료를 중복 획득으로 처리하지 않는다.

## 6. 승리·막힘·deadlock

**승리:** Board가 비고 Buffer가 비고, 모든 주문이 완료됐고, 모든 piece가 Consumed이다. 예쁜 완료 이미지가 다 보인 것만으로 승리시키지 않는다.

**표면적 막힘:** 정규화한 상태에서 보낼 목적지가 있는 논리 selectable piece가 없다. 보관대가 꽉 차도 즉시 실패가 아니다. 매칭 주문으로 직접 보낼 수 있으면 계속한다.

**깊은 deadlock:** 지금 움직일 수 있지만 어떤 미래 선택으로도 승리할 수 없는 상태. solver가 이를 증명할 수 있다. 표준 모드는 모든 실수를 즉시 막아 주지 않는다. 힌트 요청 시 “이전 선택으로 돌아가면 이어갈 수 있어요”와 되돌아갈 지점을 제공한다. solver 시간 초과를 deadlock 증명으로 취급하지 않는다.

**조작상 막힘:** 논리 선택은 가능하지만 현재 시점에서는 가려져 있다. 회전으로 해결한다. 힌트는 해당 piece가 실제로 보이는 카메라 자세도 제공한다. 모든 허용 시점에서 가려진 조각이 있다면 콘텐츠 검증 실패다.

해답은 유일할 필요 없다. 독립 조각을 어느 순서로 치우든 되는 여러 해답을 권장한다. “초기 상태에서 적어도 1개의 해답”과 “아무 선택이나 해도 풀림”을 혼동하지 않는다.

## 7. 예제로 전체 규칙 확인

작은 설명용 9묶음 레벨이다. 표준 레벨 크기와 무관한 명세 fixture다.

- 초기 주문: 빨강 R(0/3), 파랑 B(0/3). 다음 주문: 초록 G(0/3).
- Board: g1,g2,g3 / r1,r2,r3 / b1,b2,b3.
- blocker: g1→r1, g2→r2, g3→r3, r2→b2, r3→b3. b1과 초록 3개는 초기 selectable.
- Buffer 용량 5, 모든 묶음은 1단위.

| 입력 후 | R | B | 보관 | 새로 열린 것 / 효과 |
|---|---:|---:|---|---|
| g1 | 0 | 0 | g1 | r1 선택 가능 |
| r1 | 1 | 0 | g1 | — |
| b1 | 1 | 1 | g1 | — |
| g2 | 1 | 1 | g1,g2 | r2 선택 가능 |
| r2 | 2 | 1 | g1,g2 | b2 선택 가능 |
| g3 | 2 | 1 | g1,g2,g3 | r3 선택 가능 |
| r3 | 완료 | 1 | 비어 있음 | R완료→G주문 활성→초록 3개 자동 이동→G완료; b3 열림 |
| b2 | 비활성 | 2 | 비어 있음 | — |
| b3 | 비활성 | 완료 | 비어 있음 | 9개 Consumed, 승리 |

이 예제에서 r3 선택 한 번을 되돌리면 R=2, B=1, 보관=g1,g2,g3, 다음 주문=G로 모두 돌아간다. 자동 초록 수집·그림 공개도 함께 복원한다. 애니메이션 4개를 따로 undo하지 않는다.

## 8. 카메라·터치

- 세로 화면. 한 손가락 drag=회전, tap=선택, 두 손가락 pinch=확대, 두 손가락 centroid 이동=pan.
- 드래그 임계 10dp, 탭 최대 250ms를 시작값으로 사용한다. 둘째 손가락이 닿으면 그 gesture 전체에서 tap을 취소한다. 장치별 튜닝값이며 원작 수치 아님.
- 가상 trackball로 전체 방향 관찰을 허용한다. 카메라 자세는 논리 state hash에 들어가지 않는다.
- 재중앙 버튼은 **남은 논리 Board 조각의 bounds**로 맞춘다. pointer down 중에는 pivot을 움직이지 않는다.
- 남은 bounds에 자동으로 조금씩 접근하되, 매 선택마다 화면이 튀지 않게 0.4초 보간·최대 변화율 제한. 사용자가 pan/zoom 중이면 자동 보정 보류.
- 멀리서 작은 조각을 눌렀을 때 tap target은 화면상 확대하되, 가려진 다른 조각을 관통 선택하지 않는다. 후보가 겹치면 더 가까운 보이는 조각만 받는다.

## 9. 불변식과 승인 조건

1. piece는 정확히 한 location에만 존재한다.
2. 색별 총 수량 = Board + Buffer + 미완료 Order + Consumed. 어떤 도움도 몰래 실을 소실시키지 않는다.
3. 모든 order의 색별 요구 합계 = 해당 색 piece 개수. 기본 모든 색 수량은 3의 배수다.
4. Buffer 점유≤B, order 점유≤3. 자동 처리 후 추가 이동 가능 Buffer piece가 남지 않는다.
5. 같은 state+command는 같은 state+events를 만든다. GPU·카메라·프레임률·난수 라이브러리에 의존하지 않는다.
6. restart는 동일 levelHash를 재현한다. 새로운 퍼즐은 별도의 “다른 배치” 명시 기능에서만 제공한다.
7. 앱 종료·undo·두 번 tap·동시에 두 order 완료·큐 고갈·보관 포화 후 직접 매치는 회귀 검증 필수다.

원작 근거 및 불확실성은 [01_REFERENCE_GAME_ANALYSIS.md](01_REFERENCE_GAME_ANALYSIS.md), solver와 데이터 인증은 [05_LEVEL_SYSTEM.md](05_LEVEL_SYSTEM.md)를 따른다.
