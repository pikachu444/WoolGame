# 개발 순서와 통과 기준

현재 단계는 조사·설계다. 이 문서 작성 중 게임·Unity 프로젝트·원작 자산을 만들거나 추출하지 않았다. 이후 개발을 시작할 때 따르는 계획이다.

## 1. 먼저 해결할 불확실성

| 위험 | 지금 아는 것 | 다음 확인 | 막는 결정 |
|---|---|---|---|
| 원작 규칙 불일치 | 공식 설명·이미지·리뷰는 확보, 영상 동작 미검증 | 01의 E1~E3, 독립 영상의 연속 플레이 | 원작 동일 규칙 주장·대량 레벨 동결 |
| 실제 애니메이션 차이 | 긴 실 곡선은 이미지에 보임, timing은 미확인 | E5 프레임 관찰 | ‘원작 타이밍 재현 완료’ 주장 |
| 후반 구조 오판 | 117 영상 후보와 158~1400 리뷰 보고 | E4, 실제 레벨 화면 포함 중후반 플레이 | 원작 후반 수량·기믹 확정 |
| 털실이 플라스틱처럼 보임 | 세 단계 표면 구조가 필요하다는 아트 분석 | 실제 Unity 렌더 A/B | 대량 모델 제작 |
| 자동 감기 품질 | 단순 부품은 procedural에 적합 | 둥근·납작·분기 부품 3종 | 임의 모델 일괄 변환기 약속 |
| 논리/겹침 불일치 | solver만으로 실제 터치 보장 불가 | geometry·view certificate | 인증 없는 레벨 배포 |
| 모바일 발열 | 예산만 제안, 실측 없음 | 실기기 15분 | 60fps 보장·콘텐츠 상한 고정 |

추가 공개 영상 조사는 후속 개발자가 01의 구체적인 목록과 게이트에서 이어 간다. 사용자의 녹화에 의존하지 않는다. 재생이 계속 불가능하다면 근거 상태를 그대로 남기고, 독자 후보 규칙의 R&D까지만 진행한다. **조사 부족을 묻어 둔 채 원작 재현을 완료했다고 발표하지 않는다.** 독립적인 털실 rendering 실험은 이와 병행할 수 있다.

## 3. P1: 짧은 논리 prototype

한 화면에 단순 조각으로 9묶음 규칙 fixture를 만든다. 입력 한 번의 destination 선택, order 완료, 큐 교체, buffer 자동 이동, 새 selectable, undo를 event trace로 볼 수 있게 한다. 05의 12조각 반례도 넣어 초기 SAT와 잘못된 선택 후 UNSAT를 구별한다.

이 단계의 종료 조건은 규칙을 설명하고 정확히 재생하는 것이다. 그림이 없어도 괜찮지만 여기서 여러 주를 보내지 않는다. 실제 원작 E1~E3가 후보와 다르면 이 작은 단계에서 수정한다. R&D용 규칙이 바뀌어도 아트 경로·재질 연구가 버려지지 않게 ID와 계층을 분리한다.

## 4. P2: 즉시 시각 품질 검증

처음 Codex가 구현할 중심 도구는 **WoolLab**이다. 독립 모델 수십 개를 만드는 도구부터 시작하지 않는다.

WoolLab에 둥근 씨앗 부품, 납작한 꽃잎 부품, 짧은 분기 줄기 부품을 배치한다. 같은 카메라·조명에서 macro tube만, micro normal 추가, 부드러운 grazing 효과 추가를 전환한다. 감기 두께·pitch·단면 수·normal scale·smoothness를 비교한다. 화면 한쪽에는 선택 실이 스풀로 이어지고 감기는 단일 interaction을 둔다.

이 단계에서 반드시 확인할 것:

1. 둥근 윤곽을 실제 실이 만들고, 화면을 돌려도 평면 줄무늬처럼 무너지지 않는다.
2. 밝은색 실도 홈이 읽히지만 검은 줄로 갈라지지 않는다.
3. 실 제거가 전체 덩어리 축소·alpha fade처럼 보이지 않고 경로를 따라 진행된다.
4. 실의 출발점·움직이는 끝·스풀 위치가 연결된다. 카메라를 돌려도 실이 끊기지 않는다.
5. Android에서 선택 한 번의 geometry update에 눈에 띄는 hitch가 없다.
6. 현재 화면의 vertex·triangle·draw call·texture·frame time 수치를 기록한다.

원작 이미지와 나란히 보는 비교는 스토어 홍보 배경의 화려함보다 조형 내부의 감김·표면·조명·가독성에 초점을 둔다. 실제 동작 자료가 확보되기 전에는 촉각 애니메이션이 원작과 일치한다고 평가하지 않는다.

## 5. P3: 높은 목표의 vertical slice

독자 모티브 예시로 ‘구름 씨앗을 품은 작은 찻잔 화분’을 사용한다. 원작 특정 모델의 귀·얼굴·장식·부품 배치와 대응시키지 않는다. 찻잔·새싹·둥근 씨앗이라는 일반 요소를 새로운 비율과 실 방향으로 구성한다. 모티브는 03의 승인 과정에서 바꿀 수 있다.

첫 완성 레벨의 목표는 약 30묶음·4색·부품별 2~3층이며, 실제 감기 품질과 solver 결과에 따라 조정한다. 색별 수량은 3의 배수, 기본 주문/보관은 2/5다. ‘30’이라는 숫자를 맞추려고 쓸모없는 작은 조각을 붙이지 않는다.

완성 범위:

- 시작 상태의 매력적인 framing, 처음 보는 사람이 이해할 수 있는 짧은 안내.
- 탭/회전/줌/pan, 선택 불가 이유, 안전한 hit 영역.
- 한 실의 pull·unravel·transfer·spool winding, 연쇄 order 완료.
- 지지 부품 제거와 새 실 노출, 작은 그림의 진행.
- 완성 연출, 초기 조형이 복원된 도감 감상.
- undo·힌트·재시작·편안하게·저장·앱 중단/복귀.
- 효과음과 약한 진동, 각각 음소거 가능.
- 비행기 모드 실행, 일반/낮은 품질 모드의 실제 기기 결과.

### 통과 기준

03의 여섯 아트 축 모두 4점 중 3점 이상을 요구한다. 따뜻한 표면·실 풀림·색 가독성은 4점을 목표로 한다. 이 점수는 원작과 75% 일치한다는 통계가 아니라 제작팀의 심사표다. 실제 사용자에게 원작 공개 화면과 우리 실제 실행 화면을 함께 보여 주고, 어느 부분이 초라하거나 어색한지 구체적으로 묻는다.

퍼즐은 기본칸으로 풀리고 모든 해답 조각이 보이고 눌려야 한다. 15분 실행에서 04의 성능 목표에 근접해야 하며 편차·발열·기기 모델을 기록한다. 아트가 좋지만 20fps이거나, 60fps인데 플라스틱처럼 보이면 둘 다 실패다.

## 6. P4: 작은 완성판

첫 5모델을 만드는 동안 부품 제작·가이드 수정·감기 생성·수동 cleanup·Unity 검수에 걸린 실제 시간을 나눠 기록한다. 자동 변환 성공률도 기록한다. 이 수치가 나오기 전에는 100모델 일정이나 비용을 확약하지 않는다.

12모델을 40레벨로 편성할 때 같은 모델이 바로 반복되지 않게 하고, 재사용 시 의존 경로·주문 계획을 바꾼다. 모양이 같은 변형을 도감의 새 모델로 세지 않는다. 각 레벨은 해답 인증, geometry 접근성, 기본 성능 예산, 최근 콘텐츠 유사도 검사를 통과한다.

튜토리얼 이후 2~3개 레벨씩 실제 사용자에게 플레이하게 하고 재미·조작·아트·피로를 나눠 관찰한다. 서버나 analytics는 필요 없다. 도움을 쓰는 빈도를 수동 관찰할 수 있지만 이를 광고 노출이나 난이도 조작에 연결하지 않는다.

## 7. 작업량 예산

아래는 측정 전의 **계획용 인간 검토·개발 집중 시간 범위**다. Codex 실행 시간이나 완성 보장 일정이 아니다. 엔진 경험·기기 환경·아트 기준에 따라 크게 달라진다.

| 작업 | 계획용 범위 | 변동 원인 |
|---|---:|---|
| 추가 공개 동작 조사·규칙 교정 | 8~24시간 | 영상 접근성과 중후반 자료 |
| P1 논리 prototype | 12~24시간 | 규칙 변경·solver 상태 축약 |
| P2 visual R&D | 40~100시간 | 감기 형태·재질·풀림 연결 |
| P3 한 레벨 vertical slice | 60~120시간 | 아트 polish·Android·UI/저장 통합 |
| P4 12모델·40레벨 완성 | 추가 100~220시간 | 모델당 수동 cleanup·콘텐츠 심사 |
| 합계 | 약 220~490시간 | 첫 5모델 실측 후 재산정 |

주 10시간이면 단순 나눗셈상 약 22~49주 규모다. 병렬 생성이 된다고 미술 판단과 실제 폰 확인이 사라지지는 않는다. 더 작은 범위가 필요하면 6모델·15~20레벨로 줄이고 visual slice 품질은 유지한다.

현금 지출은 Unity Personal 조건 충족·Blender·직접 만든 모델/소리 경로라면 필수 외부 자산 구입 없이 시작할 수 있다. 기존 PC·Android 기기가 있다는 가정이다. Codex 사용료·전기·기기 구매·선택적 AI3D 비용은 별도이며 현재 계정 요금을 추정하지 않는다. AI3D 생성 비용 비교는 04를 따른다.

## 8. 실패 시 방향 전환

| 문제 | 먼저 바꿀 것 | 피할 반응 |
|---|---|---|
| 털실이 플라스틱 같음 | macro 감기와 미세 normal의 비율, 밝기·광택·그림자 | 털 shell 수만 무작정 늘리기 |
| 모델 자동화 실패 | 분기·구멍을 부품 분할하고 가이드 추가 | 임의 mesh에 자동 감기가 완벽하다고 주장 |
| 실 풀림이 끊김 | 경로 길이·end point·spool 좌표 계약 | 단순 fade로 영구 대체 |
| solver가 느림 | 작은 모델·witness 생성·정확한 memoization | 시간 초과를 불가능으로 오판 |
| 그래프가 외형과 어긋남 | template의 감기 방향·잠금 표식·geometry 수정 | 보이지 않는 blocker를 더 붙이기 |
| 발열·GPU 부하 | 숨은 geometry·LOD·shadow·draw call부터 측정 | 모든 micro detail 제거 |
| 콘텐츠가 반복적 | 실루엣 family 확대, 모델 수를 솔직히 축소 | 재색칠 100개를 새 모델이라고 부르기 |

## 9. 단계 종료 보고 형식

각 단계는 실제 산출물 경로, 실행한 검증과 로그, 실제 렌더 이미지, Android 기기/빌드 정보, 남은 위험, 다음 하나의 목표를 남긴다. 제안한 성능 수치와 측정한 값을 같은 열에 섞지 않는다. 구현되지 않은 Editor 명령이나 존재하지 않는 APK 링크를 완료 보고에 넣지 않는다.
