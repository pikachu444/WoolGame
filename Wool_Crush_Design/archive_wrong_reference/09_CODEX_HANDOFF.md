# 다음 Codex에게 전달할 개발 지시문

아래 ‘전달할 지시문’부터 끝까지, 01~08·10 문서와 함께 후속 개발 세션에 제공한다. 이 파일은 지시문이며 이번 조사 단계에서 구현이 이루어졌다는 뜻이 아니다.

## 전달할 지시문

나는 아내를 위한 Android 오프라인 털실 퍼즐 게임을 만들고 있다. 참고 대상은 Snap Brain Games / WINLON PTE. LTD.의 Wool Master 3D, Android `wool.master.screw.match.coloring`, iOS `6743842802`다. 이름이 비슷한 Wool Crush·TechArts 게임과 혼동하지 마라.

첨부한 01~10 문서를 먼저 읽고 현재 단계·불확실성·품질 기준을 유지하라. 원작 APK·코드·모델·텍스처·사운드·레벨을 추출하거나 복사하지 마라. 특정 캐릭터나 모델 배치를 재제작하지 마라. 공개적으로 보이는 높은 수준의 털실 미감과 퍼즐 경험에서 배우되 독자 형태·코드·데이터를 만든다.

광고·인앱 구매·분석 SDK·로그인·온라인 서버·재화 상점·구독을 넣지 마라. 모든 정상 레벨은 기본칸으로 풀려야 한다. 플레이어 실수는 가능하되 무제한 undo와 무료 도움으로 복구한다. 원작처럼 보이기 위해 광고 UI나 코인 영역까지 복제할 필요는 없다.

### 1. 착수 시 현재 상태부터 확인

기존 프로젝트가 있으면 파일·AGENTS.md·엔진 버전·미완료 변경을 확인하고 보존하라. 신규 프로젝트라면 Unity 6000.3.23f1 / URP를 기준으로 만들고 Input System 1.20.0, Splines 2.9.0, Editor 대응 uGUI/TMP·Test Framework만 우선 사용하라. core 패키지의 숫자 patch를 추정하지 말고 실제 해결된 manifest와 lock 파일을 기록하라.

Android 모듈·Hub 제공 JDK/NDK·Editor 실행 가능 여부를 먼저 확인하라. 실행할 수 없으면 막힌 정확한 단계와 지금 검증 가능한 범위를 알리되, 빌드하거나 실행하지 않은 것을 성공이라고 보고하지 마라. 엔진이 없는 상태에서 수백 줄의 추측성 scene YAML을 만드는 방식으로 완료를 주장하지 마라.

### 2. 원작 규칙의 미확인을 보존

01은 공개 이미지 18개·리뷰 40개·영상 목록을 조사했지만 실제 동영상 재생 프레임은 확보하지 못했다. E1~E5가 미완료다. 3단위 수집, 기본 수집대 2개, 보관 5칸, 논리 blocker는 우리 후보 사양이며 원작과 동일하다고 확정된 값이 아니다.

공개 영상에서 독립 제작자 2명의 실제 연속 플레이를 조사하고 시작·첫 수집 완료·보관 자동 이동·가림·실패를 타임스탬프로 남겨라. 중후반은 화면에 표시된 레벨 번호를 확인하라. 영상 제목이나 검색 설명을 플레이 관찰로 바꾸지 마라. 확인이 계속 불가능하면 그 한계를 남기고 독자 규칙 R&D까지만 진행하라. 대량 레벨의 규칙 동결과 원작 동일성 주장은 보류한다. 사용자에게 원작 파일이나 녹화를 먼저 요구하지 마라.

### 3. 첫 구현 목표: 작은 Core fixture와 WoolLab

첫 작업에서 전체 게임이나 수십 레벨을 만들지 마라. 아래 두 개를 연결할 수 있는 작고 검증 가능한 기반을 완성하라. 논리 fixture를 만든 다음 즉시 visual R&D로 넘어가라.

**A. 순수 C# Core fixture**

- 02의 9조각 R/B/G 예제를 그대로 독자 명세 fixture로 구현한다.
- Board/Buffer/Order/Consumed, blocker DAG, 고정 OrderQueue, 낮은 슬롯 우선, oldest buffer 자동 이동을 구현한다.
- 한 명령에서 전체 연쇄를 결정적으로 계산하고 snapshot/event list를 반환한다.
- 보관이 꽉 차도 맞는 활성 주문으로 갈 수 있으면 허용한다.
- 선택 목적지가 없으면 실을 제거하지 않는다.
- 모든 색의 보관 3개를 임의로 지우는 자유형 triple-match로 바꾸지 않는다.
- solver는 SAT/UNSAT/UNKNOWN을 구분하고 witness를 정식 Core로 재생한다.
- 정상 완주·12조각 실수 경로·연쇄 완료·undo의 핵심 사례를 검증한다.

**B. WoolLab 실제 Unity 장면**

- 둥근 부품·납작한 부품·분기 부품의 독자적인 3개 geometry sample을 만든다.
- 실제 macro tube 경로, 안정적인 tube frame, arc-length UV, 공유 micro fiber normal을 사용한다.
- 단순 줄무늬 텍스처를 털실 최종 품질로 취급하지 않는다.
- opaque URP 재질·넓은 부드러운 key·중성 ambient·짧은 contact shadow로 시작한다.
- 재질/조명/감기 파라미터를 inspector 또는 작은 개발 UI에서 비교할 수 있게 한다.
- 선택된 실 하나를 경로 끝에서부터 풀고, transfer spline을 통해 스풀로 감는 동작을 구현한다.
- 전체 mesh 축소나 fade만으로 실 풀림을 대체하지 않는다. 실제 rope physics는 필요 없다.
- 나머지 geometry는 정적으로 유지하고 움직이는 실만 갱신한다.
- 회전·pinch zoom·pan·재중앙화와 UI 입력 차단을 구현한다.
- 실제 scene 캡처와 최초 Android 빌드/성능 기록을 남긴다.

### 4. 표현과 논리 분리

Core는 UnityEngine·Transform·Mesh·물리·실시간 clock을 참조하지 않게 하라. `pieceId`가 visual binding과 대응한다. `LevelState`와 `Session phase`를 분리하고 animation callback으로 주문이나 blocker를 계산하지 마라.

Undo는 주문·큐·보관·그림·완료 상태를 함께 복원한다. revision이 바뀌면 이전 animation을 취소한다. 앱 중단 후에는 저장된 논리 snapshot에서 시각을 재구성한다. 움직이던 실을 다시 논리 수집해 중복 진행시키지 마라.

Blender는 base part·감기 guide·baked mesh·경로 sidecar의 제작에 사용하라. 임의 3D 모델을 완벽히 자동 변환하는 도구를 첫 단계 목표로 삼지 마라. 분기·구멍·오목한 곳은 guide와 부품 분리가 필요하다. 이미지/텍스트 3D 생성 서비스는 선택적 base mesh 제안 도구이며 구매나 API 비용 발생을 임의로 진행하지 마라.

### 5. 품질 기준

03의 비율·색·빛·세 단계 표면 구조를 출발점으로 삼되 숫자를 원작에서 측정한 값처럼 설명하지 마라. 목표는 ‘털실 소재를 썼다’가 아니라, 원작 공개 화면 옆에서도 크게 초라하지 않은 포근한 3D 조형과 interaction이다.

검증 자료는 Unity에서 실제 실행한 화면을 사용하라. AI 이미지나 Blender 고품질 렌더를 Android 실행 결과로 제시하지 마라. 첫 visual gate를 통과하지 못하면 레벨을 늘리지 말고 geometry·재질·조명·풀림을 개선하라.

성능 예산은 04의 잠정 값을 사용한다. 실제 triangle/vertex/draw call·texture memory·CPU/GPU frame time을 측정하고 기준을 교정하라. 보통 Android 60fps와 낮은 사양 30fps를 목표로 하되 기기 실측 없이 보장하지 마라. 15분 연속 실행과 앱 중단/복귀를 검사하라.

### 6. 첫 작업의 완료 산출물

다음은 앞으로 구현할 계약이지 이미 존재하는 함수·파일 목록이 아니다.

| 산출물 | 완료의 증거 |
|---|---|
| 재현 가능한 Unity 프로젝트 | 고정 Editor·manifest·lock, import/compile 로그 |
| Core fixture와 solver | 실제 검증 결과와 해답 trace |
| WoolLab scene 생성 명령 | 같은 명령 재실행 시 중복 없이 같은 scene 생성 |
| 3개 sample과 단일 실 풀림 | 실제 실행 이미지/짧은 녹화, 관찰한 결점 |
| Android APK | 실제 빌드 성공과 설치 가능 여부를 구분해 기록 |
| 성능 보고 | 기기 모델·OS·빌드 모드·측정 시간·frame time·geometry 수 |
| 다음 단계 제안 | 가장 큰 남은 기술 위험 1~3개, 첫 완성 레벨로 가는 수정 |

설치·실기기 접근이 없으면 해당 행을 ‘미실행’으로 표기하라. 확인되지 않은 품질을 통과로 간주하지 마라. 사용자에게는 실제 결과·위험·다음 작업을 명료하게 전달하라.

### 7. 그 이후의 진행

WoolLab가 통과하면 08의 vertical slice를 만든다. 독자 모델 1개·약 30묶음·4색·완전한 시작~도감 흐름이 목표다. 이 한 레벨의 시각/촉각 품질과 기본칸 해답이 검증된 뒤에만 12모델·40레벨의 작은 완성판으로 확장하라.

레벨 제작은 template + procedural variation + shared Core solver를 사용한다. 논리 해답뿐 아니라 해답마다 필요한 실제 카메라 시점과 터치 가능성을 검증한다. 모델과 레벨을 별도 ID로 관리하고 색만 바꾼 모델을 새 수집품으로 부풀리지 마라.

이번 지시문의 최우선순위는 **아트와 실 풀림을 일찍 검증하는 작은 구현**이다. placeholder 콘텐츠 양산을 진척으로 대신하지 마라.
