# 핵심 의사결정 요약

2026-09-08 · 개인용 Android 털실 퍼즐 · 1페이지 요약

**권고:** Unity 6.3 LTS에서 실제 실 감김 geometry와 미세 섬유 재질을 결합하고, 높은 완성도의 한 레벨을 먼저 만든다. 이후 독자 모델 12종·40레벨의 오프라인 게임으로 확장한다. 광고·과금·로그인·분석 SDK는 전부 제외한다.

**조사 상태:** 공개 이미지 18개와 리뷰 40개를 비교하고 영상 15개 목록을 확보했다. 그러나 영상이 재생되지 않아 동작과 실제 중후반 레벨은 미검증이다. 따라서 원작의 완전한 역설계나 동일 규칙을 확정하지 않았다. 01의 E1~E5를 보강하기 전에는 원작 동일성 주장과 대량 레벨의 규칙 동결을 보류한다.

| 질문 | 결정 |
|---|---|
| 어느 정도 비슷하게 만들 수 있나? | 둥근 조형·겹겹이 감긴 실·부드러운 색과 빛·실이 풀려 감기는 만족감은 독자 구현으로 상당히 가까이 접근할 수 있다. 원작 수준 달성은 실제 vertical slice 비교 전에는 보장할 수 없다. 특정 모델·캐릭터·자산·레벨은 복제하지 않는다. |
| 가장 어려운 기술은? | 복잡한 조형에 예쁘게 감기는 경로를 만들고, 화면의 겹침·선택 가능성·논리 dependency·풀림 애니메이션을 일치시키는 일이다. solver 자체보다 기술 아트와 반복 제작이 큰 위험이다. |
| 현실적인 털실 그래픽 방법은? | Blender의 단순 base part와 수동 감기 guide → Python/Geometry Nodes의 spline tube → baked mesh·arc-length 경로 → Unity의 opaque fiber material. 움직이는 실 하나만 변형한다. 임의 모델의 완전 자동 변환과 수만 가닥 실시간 털 물리는 목표에서 제외한다. |
| 추천 엔진은? | Unity **6000.3.23f1 / URP / C#**. Input System 1.20.0, Splines 2.9.0, Editor 대응 uGUI/TMP·Test Framework. 외부 유료 플러그인은 필수 아님. |
| 레벨 생성 방식은? | **템플릿 + 절차적 변형 + solver + 시야/터치 검증.** 후보 규칙은 주문 2개·보관 5칸·같은 색 3단위. 모든 표준 레벨은 기본칸 해답 인증서를 갖는다. 실수 후 막힘은 무료 undo로 복구한다. |
| 가장 큰 리스크는? | 원작 동작 근거 부족, 자동 감기 실패, 모델당 수동 정리 시간, 모바일 그림자·geometry 비용. 원작이 광고를 위해 불가능한 레벨을 만든다는 의도는 리뷰만으로 입증되지 않았다. |
| 첫 Codex 작업은? | 작은 9조각 Core fixture 다음 **WoolLab**: 둥근·납작·분기 부품의 털실 표현과 한 실 풀림을 실제 Unity/Android에서 검증한다. 곧바로 고품질 독자 레벨 1개로 연결한다. |
| 현실적인 완성 범위는? | 첫 완성판 **12모델·40레벨**, 부족하면 6모델·15~20레벨. 같은 모델의 변형은 새 모델로 세지 않는다. 계획상 약 220~490시간의 집중 개발·검토 범위이며, 첫 5모델의 실제 제작 시간으로 재산정한다. 100모델·500레벨은 초기 약속이 아니다. |

원작 근거는 **01**, 정확한 후보 규칙은 **02**, 아트·구현법은 **03~04**, 생성·제품·엔진은 **05~07**, 단계와 복사 가능한 지시문은 **08~09**에 있다. 이번 산출물은 조사와 설계이며 production code는 작성하지 않았다.
